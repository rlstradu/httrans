=========================================
subpandaTM v2.0.0 - The Same Tools as Poanda
=========================================

Release Date: September 11, 2026

Version 2 rebuilds subpandaTM on the same foundations as Poanda, and then goes
further. It reads four subtitle formats instead of one and gives every file back
the way it came, rebuilt over the file that was opened rather than written anew.
It runs an AI on your own machine, and it knows what each format can and cannot
do, so it never offers you something that would quietly do nothing.


Shared With Poanda

Translation memory and glossary are the same code as Poanda's, not the same
idea: a fix in one is a fix in both.

Rebuilt like Poanda: sources in `subpandatm/src/`, built with Vite, and a test
suite that runs both without a browser and against the built file in a real one.
Now at httrans.org/subpandatm/, old address redirects.

Blue stays as subpandaTM's own colour in a toolbar that otherwise matches.


Four Subtitle Formats

SubRip, WebVTT, TTML (with DFXP and IMSC) and ASS/SSA — effectively everything
that lands in a subtitler's inbox.

One rule underneath all of them: **rebuild over the file that was opened, do not
write a new one**. Only the translatable pieces are opened; everything else goes
back untouched.

A format is one entry in a table — how it is recognised, read and written —
instead of an extension list plus an `if` for opening and another for saving.

Format is decided by what is inside the file, not the extension: a .vtt renamed
.srt is still WebVTT, a .dfxp is a TTML. The picker and drop zone read their
extensions from the format table.

Export takes the extension of the format it came in, and the project remembers
the format, so a job picked up tomorrow goes back out as what it was.


Reading and Writing SRT

Empty subtitles are no longer dropped: skipping one shifted the numbering of
everything after it.

Times with a full stop (`00:00:01.500`), arrows with odd spacing, and SRT
position coordinates (X1, X2, Y1, Y2) are now read — those used to make the
out-time NaN, which spread to duration, CPS and the exported file.

`<u>` and `<font color>` survive export. Opening a file and saving it
untranslated used to hand the client back something other than what they sent.

Windows line endings and the final newline are remembered with the project and
written back as the file had them.

Untranslated text goes back out untouched, without passing through the cleaner.
What the editor writes is unescaped on the way out, so `&amp;` no longer lands
literally over somebody's face.

Positioning tags like `{\an8}` no longer count as characters.

Encoding: bytes are checked before reading, so Windows-1252 and UTF-16 files no
longer turn "canción" into "canci?n". Export is always UTF-8, and you are told
what the file you opened actually was. The byte-order mark comes back if the
file had one.

Importing an already-translated file works for all four formats, not only SRT,
and it checks the times rather than just the count: a file from a different cut
can pair wrong all the way down and still look correct line by line.


WebVTT

Cue settings ride along with the timing line. Cue identifiers come back too —
in WebVTT they are what a stylesheet points at.

Header, comments, STYLE and REGION blocks, and anything unrecognised, are kept
as they came.


TTML and IMSC

The file is never re-serialised. The reader notes the exact character positions
of each translatable text and saving splices only those; no XML tree, so
indentation, attribute order, empty-tag shape and comments survive because they
were never touched.

Opening a TTML and exporting it untranslated returns the same file, byte for
byte, with tests to say so.

Inline markup travels inside the segment as in any CAT tool. `<br/>` shows as a
line break, so line counts, CPL and the red overflow work normally.

Entities are undone for the editor and restored on save, so the memory and the
AI see "Tom & Jerry".

All four time notations are read — clock times, clock times with frames, values
with a unit (`1.5s`, `100ms`, `36f`, `500t`) and bare seconds — using the file's
own `ttp:frameRate` and `ttp:tickRate`. They are written back in the file's own
notation and only when they actually moved; a paragraph that stated a duration
is answered with a duration.

Splitting and merging work: each subtitle remembers its source `<p>`, so a split
writes two with the original's attributes and a merge removes the leftover.

Indentation is not part of the subtitle — only `<br/>` breaks a line. Files with
`xml:space="preserve"` are left alone.

Italics are `<span tts:fontStyle>`, not `<i>`: mapped both ways for display and
export only, leaving the file's own markup untouched.

The encoding declaration is the one thing deliberately rewritten, since export
is always UTF-8.


ASS and SSA

Field order comes from the file's own `Format:` line, never from the manual — an
old SSA starts with "Marked" where an ASS starts with "Layer".

The text is the last field precisely because it can contain commas, so the line
is not split on every one.

Opening and exporting untranslated returns the same file, byte for byte:
header, styles, video resolution and comments included.

`Comment:` lines are not offered for translation, since they never reach the
screen, but come back untouched.

Override marks stay visible inside the segment, exactly as in Aegisub. Editor
italics save as `{\i1}…{\i0}`, because an `<i>` in an ASS appears on screen.

`\N` becomes a real line break in the editor and goes back as `\N`. Times are
read and written in hundredths and only rewritten when they moved.


The ASS Preview

Each line is painted the way it will look, from the `[V4+ Styles]` section (and
SSA's older `[V4 Styles]`, which counts alignment differently).

Colour: ASS writes `&HAABBGGRR` — transparency, blue, green, red — so reading
left to right gave the complementary colour. Decimal colours from old SSA are
read too.

Bold, italic and underline, whether from the style or from a `{\i1}` in the
text. Corner: top, middle or bottom, left, centre or right.

Size is in proportion to the main style, not the file's 1920×1080 pixels, so a
sign smaller than the dialogue still looks smaller.

Marks inside the text override the style. Marks that cannot be drawn —
`{\pos}`, `{\fad}`, `{\move}`, `{\clip}` — are stripped from the preview, stay
visible in the editor and go back into the file untouched.

Two at once: the preview is three bands (top, middle, bottom), so a sign and a
line of dialogue both show, each with its own colour, size and alignment.

The preview now follows the video itself rather than the box holding it, so
subtitles no longer land in the black band under a short video; it keeps up when
the column is resized or the player goes full screen.


Writing Formatting

Four formatting buttons instead of one — italic, bold, underline, colour — plus
a fifth that appears only with an ASS open.

Each is written the way the open format writes it: an editor `<i>` becomes
`{\i1}` in ASS and `tts:fontStyle` in TTML.

Colour in ASS is a mark inside the text, written backwards as blue, green, red.
Colouring a word used to show yellow and export white; it is converted both ways
now.

Both of the browser's ways of writing colour — `<font color>` and an inline
style — are kept; only the first used to be.

WebVTT has no `<font>` tag: colour is a class. The eight named colours write as
`<c.yellow>`; any other writes its own class and a STYLE block after the header
and before the first cue, only when needed, so an untouched file still exports
byte for byte identical. Saving twice rewrites subpandaTM's block and leaves the
file's own alone.

The editor and preview now show WebVTT colour classes, including ones the file
declares in its own STYLE block.

Colour values are normalised to hexadecimal for SRT, WebVTT and TTML, since an
`rgb()` inside a subtitle file is a colour almost no player reads. A file that
said "red" still says "red".

Verified by rendering the generated file in a real WebVTT player and measuring
the pixels.


Where The Subtitle Sits

A control for the nine screen positions, drawn as a screen with a caption in it
rather than a bare dropdown, lit up when a subtitle has been placed.

ASS: it replaces the `{\an8}`-style mark rather than adding a second one.

WebVTT: position lives in the timing line, as line and align settings. The
bottom-centre box writes nothing, because that is a player's default. Region,
size and vertical settings are left where they were.

The selector shows where a subtitle currently sits instead of always reading
blank, and a position put there by mistake can be taken off.

Checked by rendering in a real WebVTT player: the caption lands top left, in the
exact colour asked for.


What Each Format Offers

Each format declares what it can do, in the format table in `core/formatos.js`,
and the row of buttons on each card is drawn from it. What a format cannot do
simply is not there.

Italics, bold and underline: yes in all four. Colour: yes in WebVTT, TTML and
ASS.

SRT colour is neither yes nor no — no spec exists, and `<font>` is honoured by
desktop players and stripped by many broadcast pipelines. The button stays with
a small dot and an explanation on hover; it is the only marked control.

Position is offered with ASS and WebVTT. SRT has no concept of it; TTML does,
with regions declared in the header, but subpandaTM does not write those yet.

The dot sits above the button and takes no room, so the row measures the same
with it as without, and survives a change of interface language.


Splitting Subtitles

Splitting counts visible characters, closes whatever tags are open at the cut
and reopens them in the second half, as any CAT tool does. It used to cut
straight through markup — `<span tts:fon` on one side — producing a file that
would not open.

It cuts at a space or line break rather than mid-word, prefers an existing line
break, and removes empty tags left behind.

The caret position is read from the start of the field, not the text node it sat
in, so a line with formatting no longer splits in the wrong place.

A subtitle with no translation yet can now be split: the source splits at its
natural point, which is routine while timing.


The Consultation Column

Translation memory and glossary are fixed panels in a column on the right, both
in view while you translate — not floating windows over the editor.

Drag the split between them, drag the column width, collapse either one, or hide
the column. The tool remembers how you left it.

Matches and terms are cards, not three-column tables: in half a column each cell
was about a hundred pixels wide.

Four tabs on a strip of their own, the current one coming forward like a folder
tab, and the column runs to the bottom of the window.

The column has a × of its own, and TM/Glossary, QA and AI Assistant each open
their tab, stay lit, and close the column if pressed again.

One search box at the top filters memory and glossary at the same time. There
used to be one inside each panel.

PandaBot remembers a width of its own, wider than the rest. Widening the column
to hold a conversation no longer leaves half a screen of empty cards when you go
back to the memory.


Translation Memory

Nothing below 50%, at most five matches. Before, every unit produced a match, so
a working memory offered 12% matches.

Each card carries its percentage and says what it means — exact, very close,
similar, distant — with differences marked in the source: struck through means
not in yours, underlined means missing from the memory's.

Above 3,000 units the memory is indexed, so moving between subtitles stays
instant.


Glossary

A term has a part of speech, a definition and notes, on its own card. The same
card creates and corrects, so fixing a typo no longer means retyping the term.

Terms found in the current subtitle come first. Hover a highlighted source word
for its full entry, with a button to insert the translation at the cursor.

One language pair, chosen when you open the file, used by both panels. It used
to be set twice and the two could contradict each other. It shows as a button
inside each panel, spelled out in full, and pressing it changes the pair without
leaving what you were doing.

Memory and glossary are saved per project, so another client's file no longer
arrives with the previous client's terms. Carry work between jobs with TMX and
TBX.


The AI Assistant

PandaBot is a tab in the consultation column, between TM/Glossary and QA,
instead of a column of its own taking width from the editor.

It opens on a greeting in the panda's speech bubble, followed by one question
and three answers: solve problems by prompting, pre-translate every subtitle, or
type what you want.

If no AI is set up, the greeting says so with a link straight to the settings,
and all three answers say so before anything else.

Four buttons along the bottom act on the subtitle the cursor is in: Translate,
Improve, Shorten and Explain. Shorten is the one this job asks for most.

Settings are their own box, opened by that link or the cog, rather than
unfolding on top of the conversation. Inside, the panda explains what to do
first and what happens to your key, with a link to the page where that service
hands keys out. Subtitling limits sit behind an Advanced settings button.

Same assistant and engine as Poanda: Gemini, OpenAI or Claude, with your key and
no server of ours in between. Your clients' subtitles pass through no machine of
ours. The key lives in the browser, by default only until you close the tab, and
never written into a project or a backup.

Ask it anything, or have it translate the current subtitle with its context: the
glossary terms in it, what the memory says, and the neighbouring subtitles —
which matter more in subtitling, where a sentence is split across two or three
cues constantly.

Pre-translating the whole file is a folded section of the panel, not a window on
top of everything. It follows the glossary, the memory, your instructions and,
if ticked, what fits. Only empty subtitles are touched, and the output is marked
as a draft.

The typed-in "OpenAI-compatible" service and the browser's built-in translator
are both gone: one asked you to know a port and ran models that would not keep
tags, the other made a first pass with no glossary, instructions or limits.


Fitting The Limits

A tick box, on by default, tells the AI how much fits in each subtitle: the
character count from its duration and your CPS limit, capped at two lines, plus
your characters-per-line limit.

It is asked to condense — drop fillers, repetitions, vocatives, whatever the
image already says — rather than cut the sentence short. If the first answer
still runs long it is asked once more, and the shorter is kept.

A translation that goes over is offered anyway, with a warning: a long subtitle
takes a moment to trim, an empty one has to be translated from scratch.

Italics survive the round trip. Tags are swapped for markers before sending and
restored after; if a marker comes back missing, duplicated or invented, the
translation is thrown away.


Local AI

The AI Assistant can run a model inside your browser with nothing sent anywhere,
listed under "On your computer (local AI)".

**WebLLM** downloads a model into the browser and runs it on the graphics card.
You see what it weighs before committing, a progress bar shows the download, and
it stays cached, so it works offline. Needs WebGPU (Chrome, Edge or Safari 26)
and 1-5 GB on first download.

Why it matters here: nearly every audiovisual job comes with an NDA, and whether
the dialogue of an unreleased series can leave the machine decides whether AI
can be used on that job at all.

The other half, said by the panda before anything downloads: a model that fits
on a laptop does not translate like the cloud ones. Good for questions, for a
shorter alternative, for looking something up — not for pre-translating a paying
job.

Local services ask for no API key, the button says "Download and use", and a
browser without WebGPU is told so before any download starts.

The WebLLM library is fetched from a CDN only when someone picks local AI, with
the version pinned, so nobody downloads two megabytes to open an SRT.

Of WebLLM's hundred-odd variants the list shows one per model, the most
compressed, labelled with its size.

A button deletes every downloaded model, including half-finished downloads, to
get the disk space back.


Recommended Models First

The list used to be sorted lightest-first and cut at twelve, so Qwen2.5-3B,
Llama-3.1-8B and Qwen2.5-7B were never shown at all.

It now opens with "Recommended for subtitling", in order:

**Qwen2.5-7B** (5.0 GB) — the best of the lot: strong multilingually and
obedient about instructions, which matters as much here as translating.

**Llama-3.1-8B** (4.5 GB) — near enough level. Slightly more natural Spanish,
slightly less reliable at doing as it is told.

**Qwen2.5-3B** (2.4 GB) — the balance, and the default proposed. Less than half
the download and still usable.

**Llama-3.2-3B** (2.2 GB) — the light one that still translates, for a modest
machine.

Everything else stays under "The rest", lightest first. Filtered out entirely:
models built for code, maths or vision; models with a successor on the same
list; anything under a billion parameters.


Talking To Small Models

Local models were answering the wrong thing — paraphrasing when asked to
translate. The models were fine; the prompts were Spanish, long, and written for
a cloud model.

Local models now get their own prompts: in English and short, four lines instead
of eleven. The text to translate comes last and alone, since a small model does
the last thing it read.

Surrounding subtitles are dropped — context for a big model, noise for a small
one, which sometimes translated a neighbour instead. The glossary is kept,
because that is the part that cannot be guessed.

One subtitle per request when pre-translating instead of ten: asked for a JSON
list of ten, a small model returns anything but that and the whole batch is lost.

A cap on answer length, so a model that loses the thread does not spend minutes
writing into the void. Cloud services are spoken to exactly as before.

Errors from the AI core now travel as keys and are drawn in the interface
language; messages from the service itself are still shown verbatim.


The Video Column

The player sits at the top and the waveform stretches to the bottom of the
screen — no more grey gap growing with the window.

The column starts at a quarter of the width instead of a third; the third it
took came out of the subtitle cards.

Video controls are a button bar under the player, in the waveform's style,
instead of a black bar floating over the picture that appeared on hover.

Play first, then one second back and one second forward, labelled "←1" and "1→".
Stepping back a second is what you do most while placing a cue-in and it was
keyboard-only.

Playback speed is in that bar and survives loading a new file.

Preview content — original or translation — is behind a subtitle icon. Preview
size runs 1 to 10, starting at 3.

Playing the current subtitle stops a quarter of a second before the end, so the
video no longer freezes on the first frame with no subtitle on it. On a very
short subtitle it trims no more than a third.


The Waveform

A continuous waveform instead of bars: a three-pixel bar with a two-pixel gap
summarised five pixels of sound into one, so the start of a word could fall in a
gap. Every pixel is sound now.

Zoom and waveform height are two sliders, each behind its own icon. Height is
the vertical counterpart of zoom — a quiet recording is drawn almost flat — and
changes nothing but how the sound is drawn.

Zoom is a percentage now, with 100% being what used to be 40. In pixels per
second, the 100 it opened at fitted barely three seconds on screen.

A ruler under the waveform, marked second by second. Without it the waveform is
a drawing with no scale.

Subtitle regions are a tinted box with solid edges rather than a solid blue
block: the edges are what you drag and the sound stays visible. Region labels
are legible instead of 8 pixels.


The Subtitle Rows

Laid out like Poanda's segments, source and translation side by side.

The source cell carries its own counts, in the same shape as the translation's:
comparing the two is most of what deciding a line break is.

Each line's character count sits at the end of that line in the right margin,
with the total underneath and a rule above it so it reads as a sum. The figures
track the text even when a line wraps.

Whatever runs past the characters-per-line limit is lit red on those exact
characters.

Delete, split, merge with the next one and the formatting buttons sit at the top
right of the row and stay in view however narrow the column gets.

Validate is a check mark on the right of the row, vertically centred. It had
been invisible: a leftover rule left it at `display:none`.

Duration is a field like the in and out timecodes — same shape, same line.

Enter makes a line break; it used to need Shift+Enter.

Text starts centred, original and translation, since that is how a subtitle is
read on screen; alignment is configurable per column.

Empty translations say "Type your translation here…" in pale grey, and keep the
height of their original, so the CPS bar and counts do not jump when you type
the first line.

The original column has the reading-speed bar too: knowing the source was
already running fast changes what you decide when trimming.

Every button on a card sits in its own box, all the same height.


Quality Checks

QA is a tab in the consultation column, so the limits are in view while you
translate and apply as you type them.

Three checks became nineteen. Timing: overlaps, gaps, too short to read, too
long on screen, words per minute.

Text: stray and double spaces, mixed ellipses, all-caps lines, unclosed brackets
and Spanish question marks, too many lines.

Against the source: untranslated cues, repeated text, missing numbers, edge
spaces that no longer match, glossary terms that did not make it across.

Lost formatting is reported in words — "formatting missing from the source:
italics" — comparing what tags mean rather than how they are written, so the
same italic counts whether it is `<i>`, `tts:fontStyle` or `{\i1}`. Added
formatting is reported too.

That check now reads ASS marks and WebVTT colour classes. Looking for "<" found
nothing in an ASS, so it never fired there. Turning a mark off does not count as
turning one on, and position marks do not count as formatting.

Each check is one entry in a table, and the panel — filters, counts, limits —
draws itself from it.

Every check is listed with a tick box, a line saying what it looks for, its
limit, and how many subtitles it found. The count shows even when unticked,
because a count that always read zero would be worse than none. Six are on out
of the box.

Time limits are written in frames and show what that comes to in milliseconds,
since a subtitler thinks in frames and the file is written in milliseconds.

The error list lives in the tab, under a Run QA button, and stays open while you
work through it. It used to be a floating box that had to be closed to touch the
subtitle and reopened for the next error. The QA figure in the status bar and in
the header now opens that tab.

The list groups by subtitle, so a cue that trips four checks is one entry with
four reasons.

Every subtitle with something to look at carries a warning triangle at the top
of its row, level with the timecodes: amber for a warning, red for an error, and
it names what it found on hover. Without it you had to open the QA tab to learn
which cues were wrong, and by the time you were back in the list you no longer
remembered which.

"Untranslated" is off out of the box. On a file you have just opened nothing is
translated yet, so it fired on every cue at once, and a warning that is always
there is a warning nobody reads. Turn it on at the end, to catch the ones left
behind.

New check: minimum gap between subtitles. Two frames of air between one subtitle
and the next is asked for on almost every job - without it the eye does not
register that the subtitle changed. It does not fire when they overlap, since
that is a different fault with its own check.

The panda explaining the limits goes away once Run QA is pressed: before that it
is what you need to read, after it is a third of the height repeating something
already read. Its bubble now says which limits the AI actually uses - CPS and
line length, and only those, because they are what decide how much fits.

The split between the checks and the error list is a draggable divider, like the
one between memory and glossary, and it remembers where you left it. At a fixed
split, loading the list squeezed the checks into a gap showing two of nineteen.

Two things deliberately not copied from the tool this came from: a reading-speed
count that treats markup and line breaks as characters, and a formatting check
that compares tag names.


Menus And Opening

Project and File are two menus, in that order, as in Poanda. Project is the
whole job — subtitles, translation, memory and glossary — saved in a
`.subpanda`; File is what goes in and out on its own.

Recent projects, the same window Poanda has. Each row shows file name, language
pair, how much is translated and when you last touched it. Removing a row
deletes only what the browser keeps, never your file.

Tools has a Settings box holding the timecode settings and editor text
alignment, set separately for original and translation.

The Backup entry in the File menu carries a dot that lights when there is a
saved copy. It is the only sign on screen that the work is safe.

Reopening a `.subpanda` that had a video asks for that video again by name, and
lets you carry on without it. A browser cannot keep the video inside the
project, and before this the file simply came back silently mute.

No empty video column on the way in: the panda gets the screen to itself. Once
subtitles are in and the language pair set, the panda reappears in the player
and asks for the video — click it or drop the file on it.

The logo is top left in the toolbar. It used to be inside the player, where it
vanished the moment a video loaded.

Toolbar order follows the work: Project, File, Tools, TM and Glossary, QA, AI
Assistant. Plus a language selector, a version button that opens this changelog,
and a theme button that says what it does instead of showing a moon.

That changelog is read live from the site and laid out before it is shown —
version titles, sections, points — instead of the wall of plain text it was.

The Planner is a tab in the consultation column, and its session list takes the
full height of the panel.

Autosave runs every ten seconds instead of every five minutes. The interface
starts in English, like the rest of PandaTools.


Keyboard Shortcuts

"Validate this and all previous subtitles" lost its per-card button and became a
shortcut, `Ctrl+Shift+Enter` by default, reassignable like any other.

Saved shortcut profiles are merged with the factory ones instead of replacing
them, so a shortcut added in a later version reaches people who had already
saved a profile. Hand-changed keys stay as they were left.

`Alt+1` to `Alt+5` insert the first five memory matches; `Ctrl+1` to `Ctrl+5`
insert the first five glossary terms. Neither needs the mouse.

Five documentation resources, each an address with `{word}` in it and a key of
its own: select a word, press the key, and that dictionary or term base opens
with the word already looked up.

Profiles export to a `.json` and import on another computer, the factory set
comes back in one press, and there are two to choose from — Windows/Linux and
Mac.


Appearance

Scrollbars are painted by the tool in both modes: in dark mode the browser's
light grey bar was the brightest thing on screen.

The blue border on the current subtitle is the same thickness on all four sides,
with a thicker bar down the left.

The divider between video and subtitle list is the tone of a scrollbar. In dark
mode dividers and scrollbars are lighter than the panel behind them, not darker.

Subtitle cards are one colour throughout instead of coming out in bands.

In dark mode the reading-speed bar uses muted tones and the timecodes sit a
shade below white, so three bright fields no longer pull the eye ahead of the
subtitle.

The three draggable dividers are paler and each carries a short blue grip,
visible before you touch it and lit while you drag.

Dropdowns are the tool's own rather than the operating system's, which drew
three different looks on one screen.

Both pandas have a soft shadow so they rest on something. The top bar is a
little taller and the logo a little bigger.


The Colour Picker

Picking a colour did nothing on macOS: the system picker is a separate window
and takes the focus, so by the time a colour was chosen there was no selection
left to paint.

The selection is noted before the picker opens and restored before the colour is
applied. The same applies to the position control.

It is noted again after each colour. Applying a colour wraps the text in a new
element, so the spot noted when the picker opened no longer exists: the first
colour took and the second did not, which is exactly what a colour picker is
for - trying tones until one is right.


Bug Fixes

Waveform regions were redrawn on top of one another and the clearing function
skipped every other one, so markers piled up duplicates — invisible until you
dragged one and the copy stayed put.

Five labels in the AI settings dialog were English-only and came out blank in
Spanish.

The Planner's Calculate button was stuck in Spanish: its attribute read
`data-i1admin` instead of `data-i18n`. There is now a test that reads the page
and reports misspelled attributes, missing keys, and keys present in one
language only.

The two timecode fields had not responded to typing since the tool was split
into modules: their handlers were HTML attributes looking for a function that
was no longer global.

Waveform region labels had lost their styling after a library update — it draws
inside a shadow DOM, where the page's stylesheet does not reach.

The consultation column no longer stretches with the subtitle list, which used
to push the glossary off the bottom of the screen.

Leaving the translation field no longer blanks the memory and glossary. Anything
that moved the cursor out triggered a fresh search with nothing to search
against; nothing was ever lost but the display.

Importing a TMX ran two handlers, the second calling a function that no longer
exists, leaving whatever came after half done.

The Insert button on memory and glossary cards had dark text on dark blue —
styles inherited from Poanda, whose brand colour is a light pink.


Gone In This Version

The subtitle Notes panel is gone. It held up to three alternative translations
per cue, each with its own counts and an Insert button, saved inside the
project.

PandaBot does that job now, and from where you are already writing: Improve
rewrites the current line, Shorten gives you one that fits.

Projects saved with notes still open, and the subtitles, memory and glossary all
come back. The notes themselves no longer have anywhere to show.


Loose Ends

The export name dragged the old extension along: `pelicula.ass` proposed
`pelicula.ass_trad.ass`. The trimming now uses the format table, which knows all
of them. Same fault in the backup recovery name, also fixed.

Interface texts that still said SRT — a dialog titled "Export SRT File", a
".srt file saved successfully", a dozen more — are about subtitles now.

Libraries ship with the tool and are pinned in `package.json` instead of loading
from a CDN, so the waveform core and its regions plugin no longer disagree about
versions.

Also cleared out: a debugging `console.log` shipping in the built file, a block
of dead commented-out code, and a README that still described version 1.

The waveform was fetching the whole video a second time to draw itself, from the
temporary URL, when the player already had the bytes. That second read fails on
a file that is not fully on disk - in iCloud and not downloaded, on a network
drive - so the video played and the waveform stayed blank. It now reads the file
it was handed: no download to fail, and no second copy through memory.

When the waveform cannot be drawn it now says so in its own box instead of
leaving it empty. The message existed but was commented out, so the only trace
was a line in the browser console. It tells apart "the browser cannot read this
audio" from "the file could not be read".

subpandaTM v1.1.7 - Safety Net
=========================================

Release Date: September 9, 2026

Nothing new to look at in this one. It fixes four things that were quietly
costing work, and it adds the first automated tests the tool has ever had.

Bug Fixes

Backups no longer overwrite each other: every backup was being written to the
same row in the database, so opening a second subtitle file silently erased the
backup of the first. Backups are now kept one per file, up to the ten most
recent, and when there is more than one the Backup window lets you pick which
to restore, export or delete. Existing backups are kept.

Undo works again: undoing an edit to a translation threw an error instead of
undoing it, because of a typo that made the function read a variable belonging
to Redo, and then apply the new text rather than the previous one. Ctrl+Z now
restores what was there before, and Ctrl+Y puts it back.

Pinned library versions: the tool was loading Dexie and WaveSurfer from a CDN
without saying which version it wanted, which means whatever those projects
published most recently. WaveSurfer already has an 8.0 beta out; the day it
becomes the current release, the tool would have broken overnight for everyone,
with no change on our side. Both are now pinned to the versions it runs today.

Empty video player: on startup the player was being emptied in a way that made
the browser try to load the page itself as if it were a video, filling the
console with errors before any file was opened.

Improvements

Confirmation dialogs: deleting a subtitle, restoring or deleting a backup, and
clearing the application cache used the browser's own confirm() box, which
cannot be translated, looks different on every system and freezes the page.
They now use the same dialog as the rest of the tool, in both languages.

Local logo: the logo was being fetched from GitHub on every load. It now comes
from the repository like every other image.

Dead code removed: two earlier copies of undo(), redo(), editTerm() and
deleteTerm() were sitting in the file. JavaScript only ever ran the later
definitions, so anyone reading the earlier ones was reading code that never
executed.

Tests

There is now a subpandatm-pruebas folder with fourteen end-to-end tests that run
against the published file in a real browser: that the tool starts without
errors, that an SRT opened and saved without translating anything comes back
identical, that timecodes are read down to the millisecond, and the backup and
undo behaviour described above. See its README for how to run them.

* **Improved TMX Import and HTML Formatting Preservation: The TMX importer is now more robust and correctly interprets standard-compliant files. Crucially, any HTML formatting tags (like <i> for italics or <br> for line breaks) are now properly handled during both export and import. This means formatting is perfectly preserved when moving TMs between applications, and it will be rendered correctly in the editor, not as plain text.

* **Note on Legacy TMX Files: Due to these improvements, the importer is now stricter and will reject old TMX files that were generated with previous, buggy versions. To upgrade your old TMX files, simply load them into your new version of subpandaTM and re-export them. The new export process will automatically clean and fix the file structure, making them permanently compatible.
